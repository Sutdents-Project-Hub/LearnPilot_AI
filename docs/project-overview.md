# 智學領航 LearnPilot AI｜產品範圍與執行規劃

## 1. 文件定位

本文件是產品範圍、功能需求、畫面規劃、里程碑與驗收的主要來源。架構、資料、隱私、AI 邊界與競賽展示分別由同目錄的專項文件補充。

目前狀態：

- 專案階段：`competition`
- 產品型態：React Native 行動 App Demo
- 本輪成果：可操作的 Expo 離線競賽 Demo、分析規則與完整文件
- 產品功能狀態：已實作；僅使用合成資料與本機規則模擬
- 部署：`none`

## 2. 企劃來源與理解

本規劃已完整讀取：

- [AI 學習狀態分析系統企劃簡報](<./AI 學習狀態分析系統Jason11.pptx>)
- [智慧學習隊黑客松創意構想](<./智慧學習隊_黑客松創意構想.docx>)

兩份來源共同描述的核心問題是：學生已留下讀書時間、作答、正確率與成績等足跡，但資料分散且回饋太晚，難以辨識低效時段、偏科與成績下滑風險。

正式產品名稱統一為：

- 中文：智學領航
- 英文：LearnPilot AI
- 副標：AI 智慧學習診斷與成長導航系統
- 核心承諾：告訴學生「現在在哪裡、可能遇到什麼風險、下一步怎麼走」

原企劃提到雲端同步、跨裝置、長期加密保存、24 小時 AI 助教與真實風險預測；這些需要後端、外部服務與資料治理，與本階段「無後端 Demo」衝突，因此全部列為未來能力，不納入本階段驗收。

## 3. 目標使用者與場景

### 主要使用者

需要管理多科學習、準備考試並希望了解讀書效率的學生。第一版 Demo 暫以台灣五科（國文、英文、數學、自然、社會）為示範，不代表正式產品已限定年級或科目。

### 尚未決定

- 主要年段：國中、高中或更廣泛的學生
- 教師、家長是否成為次要角色
- 科目固定或由使用者自訂
- 真實學習資料的取得方式

上述決策會改變資料、權限與介面，不在實作時自行猜測。

### Demo Persona

使用完全虛構且匿名的「小航」作為展示學生。所有成績、學習時段與建議皆為合成資料，不得影射真實學生。

展示情境：

1. 小航投入大量時間讀數學，但最近正確率與效率下降。
2. 系統辨識晚上 19:00–21:00 為相對高效時段。
3. 數學風險分數進入注意區間，並顯示可解釋的原因。
4. 系統將高效時段分配給數學錯題複習，重新安排今日計畫。
5. 學生查看後續的成長曲線與科目均衡變化。

## 4. 產品目標與成功條件

### 產品目標

1. 把分散的學習紀錄轉成容易理解的狀態摘要。
2. 在成績明顯退步前，以趨勢與規則提示風險。
3. 將診斷轉成可立即執行的下一步，而不只顯示圖表。
4. 讓評審能在短時間看見「資料 → 洞察 → 行動 → 成長」的完整閉環。

### Demo 成功條件

- 無網路、無登入、無後端也能完成主要展示流程。
- 使用同一組 fixture 時，分析與建議結果可重現。
- 每個風險與建議都能顯示原因，不使用不可解釋的「AI 說」。
- 可在 4 分鐘內展示狀態、風險、建議與成長四個價值點。
- 畫面與文件明確標示哪些是合成資料、規則式模擬與未來能力。
- 不蒐集、儲存或傳送真實學生個資。

## 5. 核心產品循環

```text
查看／新增學習紀錄
→ 彙整個人學習時間線
→ 計算效率、科目能力與趨勢
→ 偵測風險並說明原因
→ 產生下一步策略與讀書計畫
→ 以後續合成紀錄展示改善結果
```

Demo 會以預載資料完成整個循環；「新增紀錄」只在本次 App session 修改記憶體資料，重新開啟後可回復預設情境，確保展示可重現。

## 6. 功能範圍與驗收

下列功能均已在本輪完成，並以合成資料與本機規則提供可操作的競賽展示。

### LP-01 今日總覽

內容：

- 今日完成度、總學習時間與整體效率
- 最重要的風險提示
- 一個最優先的下一步行動
- 最近一次成長變化

驗收：

- 進入 App 後能在一個畫面回答「現在、風險、下一步」。
- 所有數值可追溯到 fixture 或純函式計算。
- 沒有資料時顯示可理解的空狀態。

### LP-02 學習紀錄與時間線

內容：

- 日期、開始／結束時間、科目、單元、專注度、正確率與完成狀態
- 依日期排列的學習歷程
- Demo session 內新增一筆紀錄

驗收：

- 必填欄位有驗證，錯誤輸入不會造成分析崩潰。
- 新增紀錄後，總覽與分析能在同一 session 更新。
- 重新載入 Demo 可回復預設 fixture。

### LP-03 效率與黃金時段

內容：

- 各時段平均效率
- 高效率時段區間
- 每個結論的資料筆數與解釋

驗收：

- 少於最低樣本數時，不宣稱找到黃金時段。
- 相同輸入永遠得到相同輸出。
- 圖表同時提供文字摘要，不只依賴顏色。

### LP-04 科目能力與成長趨勢

內容：

- 五科能力概況
- 近期效率／正確率／投入時間趨勢
- 科目失衡提示

驗收：

- 可以切換科目並看見對應摘要。
- 所有圖表有標題、單位、時間範圍與無障礙文字摘要。
- 合成資料須明確標示。

### LP-05 風險預警

內容：

- 各科風險等級與分數
- 造成風險的因素
- 可執行的緩解行動

驗收：

- 區分「穩定、注意、風險」三個等級。
- 風險不是成績預言；畫面須標示為規則式趨勢提示。
- 點入風險詳情能看到來源指標與門檻。

### LP-06 個人化計畫與下一步策略

內容：

- 今日／本週待辦
- 建議科目比例、時段與複習單元
- 建議原因與可接受／略過操作

驗收：

- 建議能對應至少一個已顯示的診斷原因。
- 使用者可略過建議，不以系統結果取代自主決策。
- 計畫調整後，Demo 能展示預期影響，但不得宣稱真實成效。

### LP-07 成長回顧

內容：

- 調整前後的示意趨勢
- 已完成的學習任務與改善摘要
- Demo 結尾價值回顧

驗收：

- 清楚區分「歷史合成資料」與「預估／示意」。
- 能從此頁回到風險與計畫查看因果脈絡。

## 7. 畫面與導航規劃

建議底部四個主要分頁：

| 分頁 | 回答的問題 | 主要內容 |
|---|---|---|
| 今日 | 我現在在哪裡？ | 今日總覽、風險摘要、下一步 |
| 分析 | 哪裡做得好／需要注意？ | 黃金時段、科目能力、趨勢 |
| 計畫 | 下一步怎麼走？ | 今日任務、科目比例、建議 |
| 歷程 | 我是否正在進步？ | 學習時間線、成長回顧 |

次要頁面：

- 新增學習紀錄
- 單一科目分析
- 風險詳情
- 建議詳情
- Demo 說明／資料與 AI 揭露

四個主要分頁與「新增紀錄、風險詳情、建議詳情、Demo 揭露」次要頁面均已建立；Expo 官方 Home／Explore starter 已移除。

## 8. Demo 規則式分析實作

下列規則已由 `app/src/domain/analysis.ts` 實作與測試，但不是經教育研究驗證的正式模型。

### 效率分數

```text
efficiency = 0.45 × accuracy + 0.35 × focus + 0.20 × completion
```

- `accuracy`、`focus`、`completion` 皆正規化為 0–100。
- 若缺少必要欄位，該筆紀錄不參與效率結論並顯示原因。
- 正式產品必須重新驗證權重與專注度取得方式。

### 黃金時段

- 將紀錄依固定時間窗分組。
- 每個候選時段至少需要 3 筆紀錄。
- 取平均效率最高且高於個人整體平均的時段。
- 若樣本不足，回傳「資料不足」，不硬產生建議。

### 科目風險

風險分數 0–100，由四個可解釋因素組成：

- 近期表現下降趨勢：40%
- 投入時間低於個人計畫：25%
- 近期效率下降：25%
- 計畫完成率偏低：10%

分級：

- 0–39：穩定
- 40–59：注意
- 60–100：風險

### 建議規則

建議由明確條件產生，例如：

- 科目風險 ≥ 60 → 優先安排該科下一次複習。
- 高錯題率單元存在 → 建議錯題複習，不直接前進新單元。
- 已辨識黃金時段 → 將高風險科目排入該時段。
- 樣本不足 → 建議先補足紀錄，不產生強結論。

每則建議需包含 `reason`、`evidence`、`action` 與 `disclaimer`。

## 9. 非功能需求

### 可用性

- 主要 Demo 流程在手機直向版面完成。
- 關鍵行動不超過三層導航。
- 任何指標都有白話說明。

### 無障礙

- 文字與背景符合可讀對比。
- 狀態不只用顏色表示。
- 互動元件有可理解 label 與足夠觸控範圍。
- 圖表提供文字摘要與數值。

### 效能與可靠性

- 首次載入不依賴網路。
- fixture 與分析均在裝置端完成。
- 錯誤資料不造成白畫面；提供重設 Demo 的方式。

### 隱私與誠實揭露

- 只使用合成資料。
- 不要求登入、通知、相機、定位、通訊錄或檔案權限。
- 不使用「預測你一定退步」等確定性語言。

## 10. 明確不在 Demo 範圍

- 真實帳號、角色、家長／教師入口
- backend、database、雲端同步、跨裝置
- 第三方學習平台串接
- 真實 LLM、機器學習模型或模型訓練
- push notification 與背景排程
- 真實學生資料匯入、長期保存、備份與刪除流程
- production 部署、App Store／Google Play 發布
- 商業模式、訂閱、付款與學校管理後台
